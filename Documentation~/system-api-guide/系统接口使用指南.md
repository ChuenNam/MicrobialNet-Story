# 系统接口使用指南（业务侧）

> 本文档列出剧情系统**所有可供业务侧（宿主工程）实现 / 接入的接口与调用点**，按功能模块归类。
> 业务侧通过这些接口把"真实游戏系统"（存档、角色库、战斗、UI 等）接到剧情框架上，**剧情逻辑本身零改动**。
> 所有接口均位于命名空间 `MicrobialNet.Story`（Runtime 程序集）。

---

# 接入总览
## 总览：统一装配入口 `StoryFlowConfig`

所有接缝都在 `StoryFlowConfig` 里一次性填好，再交给 `StoryFlow.Configure(config)`。`StoryFlow` 是剧情系统的对外门面与控制组件（一个 MonoBehaviour，挂在剧情 GameObject 上）；底层 `StoryPlayer` 已 internal，宿主只经这层门面接入。

| 字段 | 类型 | 模块 | 为空时默认行为 |
|---|---|---|---|
| `Variables` | `IStoryVariableProvider` | 变量 | 示例用 `InMemoryVariableProvider`（内存变量） |
| `Events` | `IStoryEventHandler` | 事件 | 默认仅打印（`LambdaEventHandler`） |
| `Text` | `IStoryTextProvider` | 文本/本地化 | 默认透传原文（identity） |
| `Characters` | `IStoryCharacterResolver` | 角色 | 运行时回退 `[未配置]` 占位符 |
| `Save` | `IStorySaveStore` | 存档 | 示例用 `PlayerPrefsSaveStore` |
| `GraphResolver` | `Func<string, StoryGraphAsset>` | 章节/多图 | 为空时遇章节跳转报错（不崩溃） |

```csharp
var config = new StoryFlowConfig
{
    Variables  = new InMemoryVariableProvider(localVars, globalVars),
    Events     = new StoryEventBus(),          // 注册业务事件见第二章
    // 语言实时读取：传入 Func<string>，运行时改语言立即对所有文本生效
    // （实际项目可替换为绑定设置页语言变量的委托，如 () => settings.language）
    Text       = new LocalizationTextProvider(table, () => "zh-CN"),
    Characters = new ScriptableCharacterResolver(characterAssets),
    Save       = new PlayerPrefsSaveStore(),
    GraphResolver = graphCollection.Resolver,   // 见第六章
};
storyFlow.Configure(config);
```

> 除 `Variables` 外，其余字段留空都能跑（用默认实现），适合先跑通 demo 再逐步替换。

# 服务接口接入
## 变量模块 —— `IStoryVariableProvider`

剧情里的**条件分支、赋值节点**全部通过此接口读写变量；框架不认宿主的存档/背包系统，由业务侧包装后注入。

### 方法清单

| 方法 | 签名 | 说明 |
|---|---|---|
| 存在性 | `bool HasVariable(string variableId)` | 变量是否已定义 |
| 取类型 | `VariableType GetVariableType(string variableId)` | 条件比较/赋值解析依赖类型 |
| 读值 | `bool TryGetValue(string variableId, out object value)` | 不存在返回 false，value 为 null |
| 写值 | `void SetValue(string variableId, object value)` | 赋值节点调用；不存在可由实现自行创建或忽略 |
| 快照 | `IReadOnlyDictionary<string, object> Snapshot()` | 导出全部变量只读快照（供存档） |

**默认实现**：`InMemoryVariableProvider`（内存变量，构造：`new InMemoryVariableProvider(IEnumerable<StoryVariableDef> localVariables, IEnumerable<StoryVariableDef> globalVariables = null)`）。

**业务实现示例**（对接宿主存档/背包）：

```csharp
public class HostVariableProvider : IStoryVariableProvider
{
    public bool HasVariable(string id) => SaveSystem.HasFlag(id);
    public VariableType GetVariableType(string id) => SaveSystem.GetType(id);
    public bool TryGetValue(string id, out object value) => SaveSystem.TryRead(id, out value);
    public void SetValue(string id, object value) => SaveSystem.Write(id, value);
    public IReadOnlyDictionary<string, object> Snapshot() => SaveSystem.Snapshot();
}
```

## 事件模块 —— `IStoryEventHandler` + `IStoryEvent`

事件节点（EventNodeData）派发时，剧情只认"事件名 + 参数 + 完成回调"，语义全在业务侧。

### 调用面接口 `IStoryEventHandler`

| 方法 | 签名 | 语义 |
|---|---|---|
| 挂起型 | `void Raise(string eventName, string payloadJson, Action onComplete)` | 事件节点用：剧情等 `onComplete` 才续走 |
| 瞬时型 | `void Raise(string eventName, string payloadJson)` | `voice:{key}` 等用：派发即忘，不挂起 |

**默认实现**：`StoryEventBus`（推荐）、`LambdaEventHandler`（仅打印）。

`StoryEventBus` 关键方法：

| 方法 | 签名 | 说明 |
|---|---|---|
| 注册（委托式） | `void Register(string eventName, Action<string, Action> handler)` | 最方便 |
| 注册（类式） | `void Register(IStoryEvent e)` | 注册一个业务事件实例 |
| 移除 | `void Unregister(string eventName)` | 按名移除 |
| 查询 | `bool Contains(string eventName)` | 是否已注册 |
| 自动发现 | `void AutoRegister(Assembly assembly)` | 扫描程序集内 `[StoryEvent]` 类自动登记 |

### 单个业务事件契约 `IStoryEvent`

| 成员 | 签名 | 说明 |
|---|---|---|
| 事件名 | `string EventName { get; }` | 须与剧情图 `eventName` 完全一致 |
| 执行 | `void Execute(string payloadJson, Action onComplete)` | 做业务逻辑；**务必调 `onComplete`**，否则剧情永久挂起 |

配套特性 **`[StoryEvent("事件名")]`**：标记后编辑器下拉自动收集该名，且可被 `AutoRegister` 发现。

> ⚠️ 易错点：`[StoryEvent]` 特性名 与 `EventName` 属性 必须一致，否则编辑器显示的名字和总线注册 key 对不上，事件节点会直接跳过。

### 业务实现示例（方式 A 委托式）

```csharp
var bus = new StoryEventBus();
bus.Register("confirm:battle_start", (payloadJson, onComplete) =>
{
    // 解析参数 → 开始战斗 → 战斗结束回调 onComplete()
    BattleSystem.Start(payloadJson, () => onComplete());
});
```

### 业务实现示例（方式 B 类 + 特性，推荐）

```csharp
[StoryEvent("confirm:battle_start")]
public class BattleStartEvent : IStoryEvent
{
    public string EventName => "confirm:battle_start";   // 与特性名一致
    public void Execute(string payloadJson, Action onComplete)
    {
        BattleSystem.Start(payloadJson, onComplete);     // 结束即续走
    }
}
// 注册：
bus.Register(new BattleStartEvent());
// 或整程序集自动：bus.AutoRegister(typeof(BattleStartEvent).Assembly);
```

## 文本 / 本地化模块 —— `IStoryTextProvider`

对白/选项抛出前，播放器按"节点 ID 派生的本地化 key"调用 `ResolveText`；命中返回译文，未命中（返回 null/空）回退显示原文。

### 方法

| 方法 | 签名 | 说明 |
|---|---|---|
| 解析文本 | `string ResolveText(string key)` | 按 key 查表；返回 null/空 → 回退原文 |

**本地化 key 规则**（与编辑器 CSV/Excel 导出一致）：
- 对话正文：`{nodeId}.text`
- 选项文本：`{choiceId}.opt.{optionId}`

**默认实现**：`LocalizationTextProvider`（构造：`new LocalizationTextProvider(StoryLocalizationTable table, System.Func<string> getLanguage)`，基于主表 `StoryLocalizationTable` 实现运行时多语言切换；`getLanguage` 每次实时返回当前语言，因此运行时改语言立即可见、切换章节不重置）。

**业务实现示例**（自定义文本变换 / 远程文本）：

```csharp
public class RemoteTextProvider : IStoryTextProvider
{
    public string ResolveText(string key) => TextService.Fetch(key); // 取不到返回 null 即可回退原文
}
```

### 标准接入：每图自带表 + 框架自动构建图绑定提供者（推荐）

本框架的**推荐本地化接入方式**是「每张剧情图自带本地化主表」+「由 `StoryFlow` 门面自动构建图绑定提供者」，宿主几乎零代码：

- **每图自带表**：每张剧情图的 `StoryGraphAsset.localizationTable` 字段已绑定它自己的本地化主表 SO（经编辑器「从图同步 Key」自动生成/回写）。**宿主无需为每张图手工准备合并表**。
- **框架自动构建图绑定提供者**：使用 `StoryFlow` 门面且**未**经 `StoryFlowConfig.Text` 注入自定义文本提供者时，`StoryFlow` 会自动以 `storyGraphAsset.localizationTable` 构造 `StoryGraphLocalizationProvider`（构造参数为 `() => ActiveLanguage`）；该提供者持有「当前图」并在章节跳转时随目标图自动切换本地化表——新图文本不再误查旧表。
- **全局语言单一控制**：`StoryFlow.ActiveLanguage`（`string`，如 `"zh-CN"`/`"en-US"`）是全局显示语言唯一权威来源：
  - 为空 → 回落当前图（或首图）本地化表的 `defaultLanguage`；
  - 设置后 → 立即对所有后续文本生效；底层 provider 在每次 `ResolveText` 时**实时读取**此值，因此运行时改语言即时生效、**切换章节也始终沿用此值，绝不回落默认语言**。
- **兜底表**：`StoryFlow.localizationTable`（Inspector）仅在某张图**没有**自带表时作为兜底，无需拖入与图同名的表。

> 若正式宿主想完全掌控文本来源（例如用自家合并表 / 远程文本 / 按章节切表），经 `StoryFlowConfig.Text` 注入自定义 `IStoryTextProvider` 即可；一旦注入，框架不再自动构建图绑定 `StoryGraphLocalizationProvider`，语言与切图逻辑完全由你提供的 provider 负责（此时通常用 `new LocalizationTextProvider(table, () => settings.lang)` 并自行处理多图）。

## 角色模块 —— `IStoryCharacterResolver`

把 `characterId` 解析为显示模型（名字 + 主题色 + 立绘）。框架不内置角色库，必须由运行时可达方式（Resources / 显式列表 / Addressables）提供，**不能依赖编辑器 AssetDatabase**。

### 方法

| 方法 | 签名 | 说明 |
|---|---|---|
| 解析 | `StoryConstants.CharacterViewModel Resolve(string characterId)` | 解析不到必须返回 `default`（isValid=false），绝不能返回裸 ID |

`StoryConstants.CharacterViewModel` 字段：`displayName`、`themeColor`、`portraitKey`、`isValid`。

**默认实现**：`ScriptableCharacterResolver`
- `new ScriptableCharacterResolver(IEnumerable<StoryCharacterAsset> assets)`
- `ScriptableCharacterResolver.FromResources(string relativePath = "Story/Characters")`（从 Resources 加载角色 SO 列表）

### 注入方式（二选一）

- 经 `StoryFlowConfig.Characters` 传入（推荐，随装配生效）；
- 或静态 `StoryConstants.BindCharacterResolver(resolver)`（全局绑定，效果相同）。

```csharp
config.Characters = ScriptableCharacterResolver.FromResources("Story/Characters");
```

## 存档模块 —— `IStorySaveStore`

剧情断点续玩进度落地。框架只认接口，不认 PlayerPrefs / 宿主存档。

### 方法

| 方法 | 签名 | 说明 |
|---|---|---|
| 写入 | `void Save(string json)` | json 已由框架序列化好 |
| 读取 | `string Load()` | 无存档返回 null/空串 |
| 是否存在 | `bool HasSave()` | 是否有有效存档 |
| 清除 | `void Clear()` | 剧情结束 / 失效时调用 |

**语义**：单槽——一个 `StoryFlowConfig` 对应一个存档槽（一张剧情图的进度）。多剧情/多槽由宿主持多个 `IStorySaveStore` 实例。

**默认实现**：`PlayerPrefsSaveStore`（构造：`new PlayerPrefsSaveStore(string key = "StoryFlow.Progress")`）。

**业务实现示例**（对接宿主云存档）：

```csharp
public class CloudSaveStore : IStorySaveStore
{
    public void Save(string json) => Cloud.SaveStoryProgress(json);
    public string Load() => Cloud.LoadStoryProgress();
    public bool HasSave() => Cloud.HasStoryProgress();
    public void Clear() => Cloud.ClearStoryProgress();
}
```

## 章节 / 多图模块 —— `GraphResolver`（委托）+ `StoryGraphCollection`

`JumpChapter` 节点（章节跳转）和运行时多图加载，通过图加载器按标识取目标图。

**类型**：`Func<string, StoryGraphAsset>` —— 输入跳转标识（章节名或 storyId，语义由宿主定），返回目标 `StoryGraphAsset`（图资产句柄）；找不到返回 null（触发明确错误，不崩溃）。

### 推荐辅助类 `StoryGraphCollection`

| 方法 | 签名 | 说明 |
|---|---|---|
| 注册（资产） | `void Add(string key, StoryGraphAsset asset)` | 标识建议用 storyId/章节名；内部经 `RuntimeStoryGraph.FromAsset` 编译为运行时图 |
| 取图 | `StoryGraphAsset Resolve(string key)` | 找不到返回 null |
| 转委托 | `Func<string, StoryGraphAsset> Resolver { get; }` | 可直接赋给 `StoryFlowConfig.GraphResolver` |

```csharp
var graphs = new StoryGraphCollection();
graphs.Add("chapter1", chapter1Asset);
graphs.Add("chapter2", chapter2Asset);
config.GraphResolver = graphs.Resolver;   // JumpChapter 填 "chapter1"/"chapter2" 即可跳转
```

# 表现层接入与完整装配
## 表现层通知 —— `StoryFlow` 的 C# 事件 / `IStoryPresenter`（自定义 UI 用）

> 底层 `StoryPlayer` 已 internal，**宿主只能经 `StoryFlow` 这层门面**接入表现层。两种驱动自定义 UI 的方式任选其一。

### 方式 A（推荐）：实现 `IStoryPresenter`

把"显示对白 / 选项 / 结束"与"收集用户输入"收敛到一个视图组件，经 `flow.Configure(presenter)` 注入（或同 GameObject 上挂 `IStoryPresenter`，由 `StoryFlow` 自动 `GetComponent` 兜底）。接口方法：

| 方法 / 事件 | 签名 | 说明 |
|---|---|---|
| 呈现对白 | `void ShowLine(StoryFlow.Line line)` | 渲染一句对白 |
| 呈现选项 | `void ShowChoices(IReadOnlyList<StoryFlow.Choice> choices)` | 渲染选项按钮 |
| 剧情结束 | `void ShowEnd(bool showText, string text)` | 到达 End 节点；`showText=false` 时不弹任何框（自然结束），`text` 为可选的结束展示文本 |
| 剧情异常 | （不再经 Presenter） | 死路 / 缺节点 / 异常结构：仅 `StoryFlow.OnError` 事件对外派发 + 控制台 `LogError`，不弹框 |
| 请求推进 | `event Action OnAdvanceRequested` | 视图内点击对白面板时触发 → `StoryFlow` 转调 `Advance()` |
| 请求选择 | `event Action<string> OnChoiceSelected` | 视图内点击选项按钮时触发 → `StoryFlow` 转调 `Choose(optionId)` |

TMP 版 `StoryView` 只是 `IStoryPresenter` 的一种实现（位于可选模块 `com.microbialnet.story.TMP`）；宿主可自实现该接口（UGUI / IMGUI / 自绘任意 UI），或传 `null` 做 headless（测试 / 服务端）。

### 方式 B：直接订阅 `StoryFlow` 事件

不实现 `IStoryPresenter` 时，也可订阅 `StoryFlow` 的以下 public 事件驱动界面：

| 事件 | 签名 | 触发时机 |
|---|---|---|
| `OnLine` | `Action<StoryFlow.Line>` | 抛出一句对白（含讲述者、文本、语速、立绘/语音 key） |
| `OnChoices` | `Action<IReadOnlyList<StoryFlow.Choice>>` | 抛出玩家选项 |
| `OnEvent` | `Action<StoryFlow.StoryEventInfo>` | 事件节点派发（调试/视图用） |
| `OnNodeEnter` | `Action<string>` | 进入某节点（节点 ID，编辑器高亮/调试） |
| `OnEnd` | `Action` | 剧情结束 |
| `OnChapterChanged` | `Action<string>` | 章节/图切换（JumpChapter），参数为目标 storyId |
| `OnError` | `Action<string>` | 死路 / 缺节点 / 异常结构 |

### 关键结构体字段

- `StoryFlow.Line`：`SpeakerId`、`SpeakerName`、`Speaker`(CharacterViewModel)、`Text`、`Speed`、`PortraitKey`、`VoiceKey`、`appearance`(DialogueAppearanceHint)
- `StoryFlow.Choice`：`OptionId`、`Text`、`Prompt`、`PromptSpeed`、`PromptTypingMode`、`appearance`(DialogueAppearanceHint)
  - `Prompt`：选项框顶部说明文字——「带文字」选择节点的行内对白（可空 = 不显示）；自定义 UI 若要复刻框架行为：有 `Prompt` 时先按打字机揭示（参数 `PromptSpeed`/`PromptTypingMode`，与对白节点同语义），**文字打完后选项才出现**；无 `Prompt` 直接出选项（选项永不因打字配置而延迟）。点按跳过语义同对白（打字中点击 = 立即全显并出选项）
  - `appearance`：节点级外观覆盖提示（样式键/覆盖位置/策略键/保留），由视图应用；自定义 UI 可忽略（等价回到全局默认）
- `StoryFlow.StoryEventInfo`：`Name`、`PayloadJson`

**驱动推进的控制方法**（在收到 `OnLine` / `OnChoices` 后由 UI 调用）：

| 方法 | 签名 | 说明 |
|---|---|---|
| 开始 / 继续 | `void Play()` | 装配并开播；已运行则幂等 |
| 结束 | `void Stop()` | 结束播放 |
| 推进对白 | `void Advance()` | 收到 `OnLine` 后，玩家点"继续"时调用 |
| 选择选项 | `void Choose(string optionId)` | 收到 `OnChoices` 后，玩家选某项时调用 |
| 按序号选择 | `void Choose(int index)` | 按最近一次 `OnChoices` 可见列表下标选 |
| 重播 | `void Restart()` | 从入口重播、变量归零、清旧进度 |
| 状态 | `bool IsRunning` / `bool IsWaiting` | 当前运行 / 等待态，UI 判定按钮态 |
| 全局语言 | `string ActiveLanguage { get; set; }` | 运行时随时设置显示语言；切章节不回落，详见 §3.1 |

```csharp
// 方式 B 示例：订阅事件驱动自绘 UI
flow.OnLine    += line => myUI.ShowDialogue(line.Text, line.SpeakerName, () => flow.Advance());
flow.OnChoices += options => myUI.ShowChoices(options, opt => flow.Choose(opt.OptionId));
flow.OnEnd     += () => myUI.Hide();
flow.Play();
```

## 完整装配示例

```csharp
// 1) 变量（对接宿主存档）
IStoryVariableProvider variables = new HostVariableProvider();

// 2) 事件总线 + 注册业务事件
var bus = new StoryEventBus();
bus.Register(new BattleStartEvent());
// bus.AutoRegister(typeof(BattleStartEvent).Assembly);
// 也可整程序集自动发现

// 3) 文本/本地化（语言实时读取，传入 Func<string>）
//    此处 () => "zh-CN" 可替换为绑定运行时语言变量的委托
IStoryTextProvider text = new LocalizationTextProvider(localizationTable, () => "zh-CN");

// 4) 角色解析
IStoryCharacterResolver characters = ScriptableCharacterResolver.FromResources("Story/Characters");

// 5) 存档
IStorySaveStore save = new PlayerPrefsSaveStore();

// 6) 多图
var graphs = new StoryGraphCollection();
graphs.Add("chapter1", chapter1Asset);
graphs.Add("chapter2", chapter2Asset);

// 7) 装配
var config = new StoryFlowConfig
{
    Variables = variables,
    Events = bus,
    Text = text,
    Characters = characters,
    Save = save,
    GraphResolver = graphs.Resolver,
};
storyFlow.Configure(config);
```

## 附录：接口速查表

| 模块 | 接口 / 类型 | 业务侧动作 | 默认实现 |
|---|---|---|---|
| 变量 | `IStoryVariableProvider` | 实现并注入 | `InMemoryVariableProvider` |
| 事件（调用面） | `IStoryEventHandler` | 注入 `StoryEventBus` | `LambdaEventHandler`（打印） |
| 事件（单事件） | `IStoryEvent` + `[StoryEvent]` | 实现并 `bus.Register` | — |
| 文本/本地化 | `IStoryTextProvider` | 实现并注入 | `LocalizationTextProvider` / 透传 |
| 角色 | `IStoryCharacterResolver` | 实现并注入（或 BindCharacterResolver） | `ScriptableCharacterResolver` |
| 存档 | `IStorySaveStore` | 实现并注入 | `PlayerPrefsSaveStore` |
| 章节/多图 | `Func<string, StoryGraphAsset>` | 提供 `GraphResolver` | `StoryGraphCollection.Resolver` |
| 表现层 | `StoryFlow` 的 C# 事件 / `IStoryPresenter` | 订阅 `OnLine/OnChoices…` 并驱动 `flow.Advance()/Choose()` | 内置 `StoryView`(TMP) 或自实现 `IStoryPresenter` |
